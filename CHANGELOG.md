# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- Project scaffold: React Router 8 (SSR) + React 19 + TypeScript (strict) + Tailwind v4
- Layered architecture (app → adapters → core) with the dependency direction enforced by lint
- Design tokens: Trade Republic-style monochrome palette, tabular numerals, dark-first theme
- Persistence: Prisma 7 + SQLite via the better-sqlite3 driver adapter. Immutable ledger schema (Instrument + LedgerEntry) with a unique constraint for idempotent ingestion
- Continuous integration: lint, type-check and build on every push and pull request
- Core domain: Money (decimal.js), ledger event types, LedgerRepository port, and the computePositions projection (weighted-average cost) with unit tests
- Ledger domain schemas (Zod, single source of truth for types and validation)
- Persistence adapter: Prisma LedgerRepository (idempotent append, chronological list) with row<->event mappers and an integration test.
- CSV ingestion for Trade Republic and Kraken on a shared ingestion layer (batch builder + persist step; card spending and non-BTC crypto filtered; dedup by source transaction id).
- Portfolio screen (index route): server loader derives current holdings from the ledger (computePositions + trade metadata), joined with instrument data and sorted via URL search params. Shows instrument, type, quantity, average cost, invested amount and realized P&L, with expandable per-position detail (ISIN, currency, asset class, first/last trade, trade count). Reusable presentation layer: es-ES formatters, centralized Spanish copy, and design-system components (Card, SleeveChip, SignedMoney, sortable table). Market-derived columns (value, unrealized P&L, weight) intentionally deferred until a price provider exists. Closed positions are excluded from the holdings view
- Market-data provider (Yahoo): agnostic MarketDataProvider and PriceRepository ports in core; YahooMarketDataProvider adapter over the chart endpoint with a pure, tested response parser; append-only PriceSnapshot table (idempotent per instrument+quote-time). Each instrument carries an optional quoteSymbol (EUR venues preferred to avoid FX), set locally via pnpm prices:map <ISIN> <SYMBOL> or Prisma Studio and never written by ingestion, so a public repo never discloses holdings. pnpm prices:sync fetches quotes for instruments that have a symbol and persists snapshots, reporting the rest. Prices are not yet surfaced in the UI
- Holdings screen now shows market data: Valor, P&L (unrealized) and Peso columns, plus total value, total unrealized P&L and an "Actualizado hace X" freshness indicator. Values come from the latest persisted price snapshot (base-currency quotes only; foreign-currency quotes await FX). Unpriced positions show "—" and sink to the bottom; default sort is portfolio weight. Realized P&L moves to the expandable detail. New pure projection computeMarketValues (value/unrealized/weight) with tests
- Portfolio-level projections for the upcoming summary screen: computePortfolioSummary (totals, unrealized/realized P&L, return; unpriced holdings excluded from both value and invested so the headline can report them instead of implying a loss), computeAllocation (value grouped by a caller-supplied classification, keeping core free of instrument metadata), computeTopPositions (largest priced holdings with per-position P&L) and computePortfolioInvestedVsValueSeries (per-instrument series merged on the union of timestamps, carrying each holding forward so gaps don't carve false dips). All pure and unit-tested; not yet surfaced in the UI
- Shared UI primitives extracted for reuse across screens: the range selector moves to the design system with its range logic (parse, filter) pulled into a pure, tested module; the invested-vs-value chart body is split from the instrument card so the same shape serves a single holding and the whole portfolio; plus a greyscale donut, a stat tile and shared signed-figure helpers
- Summary screen, now the home route (holdings move to /cartera): headline portfolio value with its change over the selected range, portfolio evolution chart, invested/unrealized/realized/position tiles, allocation donut by instrument type, and the five largest holdings. The range selector lives in the header and is driven by URL search params, so a ranged view is shareable and survives a reload. The headline change reports the movement in unrealized P&L rather than in market value, so a contribution is not mistaken for a gain. Holdings without a usable base-currency price are excluded from the totals and reported in the hero instead of being silently dropped
- Historical price backfill: pnpm prices:backfill [ISIN] [range] fetches daily closes from Yahoo and persists them, so charts can draw the past instead of starting at the first sync. Deliberately skips the freshness filter that prices:sync applies — every candle is old by definition, and discarding old quotes is right for "what is this worth now" and wrong for "what was it worth then". Requests are sequential to stay under the unofficial endpoint's rate limits, and re-runs upsert on (instrument, quote time) rather than duplicating. New tested pure parser for the close series, which drops sessions with no close rather than interpolating a price that never traded
- Movements screen (/movimientos): the full ledger — trades, dividends, deposits, withdrawals and interest — with pagination driven by the URL, so a page is shareable and the back button works. Amounts are the real cash flow rather than the gross: costs never help you, so they are added to what you pay and subtracted from what you receive, which is one rule (amount = signedGross - costs) covering purchase fees and dividend withholding alike. The column reconciles against both the bank statement and the invested total. Price stays a price mark (gross / quantity), since a fee is not a price and TWR is measured on price marks. A single table now serves this screen and the asset detail, which consequently gained its dividends
- Instruments screen (/instrumentos): classify exposure from the UI instead of the CLI, with a select that makes an invalid kind unspellable and the resolved leaf shown beside it. Held value and a closed-position badge sit on the same row, because a closed position derives every number as zero and a wrong mapping then looks exactly like a right one — the blindness that let a wrong price symbol through unnoticed. This is the app's first mutation: a native React Router action validating with the same Zod schema the CLI uses, rather than a form library, since the form is one select and one text field
- Fund compositions are imported by dropping the issuer's CSV onto its row in the instruments screen — no command, no cleaning the file first. The preview is parsed in the browser, so what was understood appears instantly and nothing is uploaded until it is confirmed; the same pure parser then runs again on the server, which trusts nothing it is handed. The detected columns are stated rather than asked about, with the dropdowns to correct them a click away: they are an answer, not a question, and putting three selects in front of someone implies a decision they do not have to make. Constituents are sorted by weight rather than left in the order the issuer shipped, since that order is not a contract and a preview of twelve arbitrary rows verifies nothing. The upload is offered only on equity funds: holdings on a gold ETC would turn bullion into a basket of companies, and the server refuses them too rather than storing a lie waiting to be believed. An as-of date is read from the issuer's own preamble when it is unambiguous — a month name or an ISO date — and refused when it is not, since "07/08/2026" is August in Madrid and July in New York and guessing is silently wrong by a month
- Fund compositions are stored and fed to the resolver, so an equity fund now expands into its constituents instead of standing as one opaque leaf. Storage is replace-only rather than append-only, unlike price history: a holdings file is a snapshot of what a fund holds today, not an event that happened, and appending would keep constituents that have left the index. The residual is derived at read time and never stored alongside the weights, which is how the earlier cost-basis bug was born. The rule that governs the portfolio governs a fund too — whatever the file does not account for becomes the fund's own UNRESOLVED leaf, so a fund published with only its top ten resolves to eleven leaves rather than pretending ten add up to a hundred. computeExposures is untouched: it already took an array of weighted leaves, so a fund going from one leaf to nine hundred is not a new shape
- The allocation screen merges leaves by canonical identity, so a company held directly and held again inside a fund appears once. Both routes are kept rather than summed away, which is the point: "11.2%" is not a decision, "9.7% you bought and 1.5% that rides inside the index" is. Canonicalisation is a separate step from resolution — one asks what an instrument contains, the other what two containers agree to call the same thing — and it touches only company leaves, since a commodity or an undecomposed fund has no share class. When several names compete for one merged leaf, the directly held position wins: that is the name on the statement, and without a rule the winner would be whichever instrument happened to be iterated first
- An ambiguous ticker is narrowed by where the holding trades before falling back to its name. Numeric tickers are normal across Asia and collide constantly — 2330 is TSMC in Taipei and something else elsewhere — which left the largest chip maker in the world split across two leaves. Bridging the venue needs a table, since OpenFIGI speaks Bloomberg's exchange vocabulary rather than ISO (Taiwan is TT, Japan JT, Germany GR), and that table is worth its upkeep for one reason: a wrong or missing entry costs nothing. It only ever narrows a candidate set that is already ambiguous, so at worst it filters nothing and resolution falls through to the name exactly as before — it can turn "ambiguous" into "resolved" but never "resolved" into something wrong
- Names are matched by containment rather than equality, because sources clip them at different widths: one issuer publishes "TAIWAN SEMICONDUCTOR MANUFAC", another the full name, and the provider its own clipped version. Containment is looser than equality, so it stays safe only because the match must be unique among the candidates — a prefix fitting two of them still resolves nothing — and a prefix under eight characters is refused outright so that "Bank" cannot reach "Bank of America"
- Canonical security identities via OpenFIGI, so the same company stops being two leaves. Issuers disagree on what to publish — three of six give an ISIN, the other three a ticker — and they hold hundreds of the same businesses, which left 726 measured collisions across one portfolio's funds. Both sides now map to a share-class FIGI: the level that links one share class across countries, which is exactly the gap, while deliberately leaving GOOG and GOOGL, or Berkshire A and B, apart — those are separate securities with separate ISINs and prices, and merging them would be wrong rather than tidy. A ticker is asked for without an exchange code, because OpenFIGI's exchange vocabulary is Bloomberg's rather than ISO and translating would mean a table to maintain; instead every listing comes back, and when they disagree the issuer's own name picks between them. That is a much narrower question than the name matching rejected earlier — Bloomberg has already bounded the candidates to the companies sharing that ticker, so the only thing left to decide is which of the two the file meant, and a name matching none or several of them still refuses. Anything unresolved keeps its raw identity and still appears with the right value — it simply does not merge. Lookups are cached permanently, misses included, and resolution runs at import time so no screen ever touches the network
- pnpm identity:resolve resolves in descending weight order, which is what makes this usable without an API key: unauthenticated the endpoint allows ten lookups per request and twenty-five requests a minute, so five thousand constituents would take twenty minutes — but nearly all of them sit in the tail that is reported rather than drawn, and a default budget of two hundred already covers every row a person can see. A free key raises that to a hundred per request and the whole portfolio resolves in seconds
- Allocation screen (/asignacion): what you actually own, once every position is resolved through to its leaves. Each bar is stacked in two segments — solid for what was bought directly, faded for what rides inside a fund — because that is the only distinction on the screen that changes what you would do: a concentration you chose can be trimmed, while the same concentration arriving through a broad index fund cannot be touched without leaving the index. The concentration threshold is drawn as a mark on every bar and is part of the scale rather than just painted on it, so "how far am I from my limit" stays answerable even when every holding sits well below it; it lives in the URL like the sort order and the chart range. The long tail is reported rather than drawn: a global index fund resolves to thousands of constituents that together came to 46% of one real portfolio, and as a bar that is simultaneously the longest thing on screen, the only one that cannot be acted on, and the reason every real holding renders as a sliver. It is a fact about the portfolio, not an exposure, so it sits in the summary. A reading card states the answer in a sentence rather than making you find it in a table, and counts every leaf that went through the look-through rather than the handful that clear the presentation threshold — reporting 18 analysed when five thousand were is just wrong. A holding reached by several routes appears once, with each route kept rather than summed away — "NVIDIA 11.6%" is not actionable, but "9.7% held directly, 1.6% inside the FTSE, 0.1% inside Automation & Robotics" is, because only the first part is a decision and the rest is the cost of owning the market. The two thresholds that get confused are separated: presentation, near half a percent, decides what is drawn and folds the long tail of a four-thousand-constituent fund into one row; concentration, near fifteen percent, decides what is flagged. Setting the first to the second empties the table into "Otros" and shows nothing. The unresolved leaf never folds however small it gets, since it is the honest measure of what cannot be analysed
- The holdings parser accepts weights published as fractions as well as percentages, and drops a trailing total row. Neither is exotic — plenty of issuers write 0.0445 rather than 4.45%, and plenty end the file with a TOTAL line, which doubled the column and made nothing look like a weight at all. The two scales cannot be confused: a percentage column summing to 1 would be a fund one percent invested, and a fraction column summing to 100 would be a hundred times its own size. The total row is dropped only when dropping it turns an unreadable file into a readable one, since a fund's smallest holding is also a last row
- The holdings parser survives exports that have been reformatted. One real file arrived pretty-printed into aligned columns, which puts a space between the delimiter and the opening quote — and a CSV reader only treats a field as quoted when that quote sits flush against the comma, so every value came back with its quotes attached. That turned a venue into "United States", a string no other issuer's file will ever agree with, and split holdings that should have merged. A wrapping pair of quotes is now removed after trimming; a quote that is part of the data, like a pipe size, is left alone
- Venue names are folded to ISO country codes, because the parser was manufacturing collisions of its own on top of the real ones: one issuer writes "US", another "United States", and a Spanish one would write "Estados Unidos" — the same listing, three strings, three leaves. Intl.DisplayNames does this with no table to maintain, since the runtime already knows every country in every locale it ships; a value it cannot fold, like "NASDAQ", is kept verbatim rather than guessed at, which would merge venues that are genuinely different. The parser now also prefers a qualifier column of countries over one of exchange names when both disambiguate, because only the former can ever agree across two issuers' files
- Holdings identities are qualified by venue, because a ticker is only unique within one. In a single real global fund, SAN is Banco Santander in Madrid and Sanofi in Paris, MRK is Merck & Co in New York and Merck KGaA in Germany, 6526 is Socionext in Tokyo and Airoha in Taipei — ninety collisions, each of which would have claimed a holding that does not exist. This is the same reason a quote symbol is IBE.MC rather than IBE. The column naming the venue is found structurally, as whichever repeating column removes the most collisions, so it lands on Region in one issuer's file and Location in another's without being told. Once the venue is part of the identity, folding is safe: two rows for one holding in one venue add up, which no longer risks Madrid swallowing Paris. ISIN files need none, since an ISIN already carries its country
- Generic ETF holdings parser: one parser for every issuer, with no issuer-specific branch anywhere. Verified against six real exports (six header layouts, two languages, files with and without an ISIN column) and the seventh issuer should need no code. The trick is that the weight column is the one whose values add up to about 100 — a signal that survives translation, reformatting and rebranding, and doubles as verification: if nothing adds up, the file is not a holdings table and saying so beats importing half of one. The header is found as the first row of three or more non-numeric cells, which skips whatever preamble, byte-order mark or non-breaking space an issuer put above it, and the as-of date falls out of that preamble for free. The identity column is picked by ISIN shape, then by being mostly unique — the check that stops a Region column of "US" and "JP" from passing as tickers. Rows with no usable identity — cash, FX forwards, an issuer's own catch-all bucket — fold into the fund's residual, so nothing is dropped and nothing is invented; a fund carrying negative cash yields a negative residual rather than a clamped zero, because the alternative hides that it is geared
- Exposure model for look-through: every position resolves to leaves with weights summing to one. A leaf is not necessarily a company — gold resolves to a commodity and BTC to a crypto asset, neither of which has constituents, so making the leaf kind explicit is what keeps them from being special cases. exposure:map sets the classification by hand because brokers do not report it: Trade Republic labels both funds and physical-gold ETCs as FUND, leaving an ETC indistinguishable from an index fund. Stocks and crypto resolve from their type; ETCs and bond funds need one command each. Anything without a holdings source resolves to an UNRESOLVED leaf carrying its own value, reported rather than spread across the leaves that are known — pro-rating it would invent a concentration that isn't there. Exposures keep each contribution instead of summing it away, so a weight can be attributed to the positions that produce it

### Fixed
- Contributions now count purchase fees, matching the cost basis used everywhere else. The KPI tile summed gross amounts only, so it disagreed with the P&L header by exactly the fees paid — 1 EUR on a single-purchase holding. Fees are money that left the account and belong in the acquisition value under foral tax rules; excluding them understated contributions and flattered returns, so reported returns now move slightly against the holder and are correct
- The summary hero's all-time change is read from the same figures the tiles render rather than differenced off the ends of the series. The series starts at the first purchase, when P&L is already negative by the fees, so differencing handed those fees back as a gain and put the hero 1 EUR above the P&L tile. Before the first purchase there was no portfolio, so all-time change is current P&L and the two now agree by construction
- A failed holdings import no longer reports itself as an unreadable file. Duplicate tickers tripped a database constraint after the file had parsed perfectly, and the error said the file could not be read — sending a person to debug the one thing that had worked. A parse failure is theirs to act on; anything else is ours, and is now logged and reported as such
- The instruments screen used two Tailwind classes for tokens the theme never defined — bg-surface-1 and text-warning. Tailwind emits nothing for an unknown token, so the select simply had no background and the closed-position badge no colour, silently. The badge now matches the existing chip style, since the palette is monochrome by design and reserves green and red as semantic signals
- Native form controls now render in the theme they are shown in. A <select>'s open popup is drawn by the operating system rather than by the stylesheet, and with no color-scheme declared the OS assumed light while the options inherited white text from the control — white on white, with only the highlighted row legible. This never surfaced before because the app had no forms
- The instruments list is ordered by value rather than by id. Ordering by id is right for a repository and useless for a person: it led with Bitcoin purely because "BTC" sorts early
- BASE_CURRENCY is declared once in the domain instead of separately in each route. Four routes each defined their own copy of the currency every projection reports in, which is exactly the kind of duplication that survives until FX lands and then diverges silently
- exposure:map now prints the resolved leaf, not just its kind, so a listing shows COMMODITY:XAG rather than a COMMODITY that could be either metal
- Portfolio sort controls: the sort labels announced to screen readers were hardcoded in the component instead of the Spanish dictionary
- InstrumentWriteData now omits the manually-set columns at the type level rather than by convention. Ingestion upserts every instrument on every import, so any column it can write is a column it will overwrite; quoteSymbol was already excluded by hand, and the exposure columns would have been silently clobbered on the next re-import
- The latest price per instrument now resolves by market time rather than by fetch time. Ordering by fetch time was safe only while every write was a single current quote; a bulk history write lands hundreds of candles with the same fetch time, which would have surfaced an arbitrary years-old price as current and corrupted every valuation in the app
