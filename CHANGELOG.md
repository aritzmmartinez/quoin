## [Unreleased]

### Added
- Project scaffold: React Router 8 (SSR) + React 19 + TypeScript (strict) + Tailwind v4
- Layered architecture (app → adapters → core) with the dependency direction enforced by lint
- Design tokens: Trade Republic-style monochrome palette, tabular numerals, dark-first theme
- Persistence: Prisma 7 + SQLite via the better-sqlite3 driver adapter. Immutable ledger schema (Instrument + LedgerEntry) with a unique constraint for idempotent ingestion
- Continuous integration: lint, type-check and build on every push and pull request
- Core domain: Money (decimal.js), ledger event types, LedgerRepository port, and the computePositions projection (weighted-average cost) with unit tests
- Ledger domain schemas (Zod, single source of truth for types and validation)
- Persistence adapter: Prisma LedgerRepository (idempotent append, chronological list) with row<->event mappers and an integration test.
- CSV ingestion for Trade Republic and Kraken on a shared ingestion layer (batch builder + persist step; card spending and non-BTC crypto filtered; dedup by source transaction id).
- Portfolio screen (index route): server loader derives current holdings from the ledger (computePositions + trade metadata), joined with instrument data and sorted via URL search params. Shows instrument, type, quantity, average cost, invested amount and realized P&L, with expandable per-position detail (ISIN, currency, asset class, first/last trade, trade count). Reusable presentation layer: es-ES formatters, centralized Spanish copy, and design-system components (Card, SleeveChip, SignedMoney, sortable table). Market-derived columns (value, unrealized P&L, weight) intentionally deferred until a price provider exists. Closed positions are excluded from the holdings view
- Market-data provider (Yahoo): agnostic MarketDataProvider and PriceRepository ports in core; YahooMarketDataProvider adapter over the chart endpoint with a pure, tested response parser; append-only PriceSnapshot table (idempotent per instrument+quote-time). Each instrument carries an optional quoteSymbol (EUR venues preferred to avoid FX), set locally via pnpm prices:map <ISIN> <SYMBOL> or Prisma Studio and never written by ingestion, so a public repo never discloses holdings. pnpm prices:sync fetches quotes for instruments that have a symbol and persists snapshots, reporting the rest. Prices are not yet surfaced in the UI
- Holdings screen now shows market data: Valor, P&L (unrealized) and Peso columns, plus total value, total unrealized P&L and an "Actualizado hace X" freshness indicator. Values come from the latest persisted price snapshot (base-currency quotes only; foreign-currency quotes await FX). Unpriced positions show "—" and sink to the bottom; default sort is portfolio weight. Realized P&L moves to the expandable detail. New pure projection computeMarketValues (value/unrealized/weight) with tests
- Portfolio-level projections for the upcoming summary screen: computePortfolioSummary (totals, unrealized/realized P&L, return; unpriced holdings excluded from both value and invested so the headline can report them instead of implying a loss), computeAllocation (value grouped by a caller-supplied classification, keeping core free of instrument metadata), computeTopPositions (largest priced holdings with per-position P&L) and computePortfolioInvestedVsValueSeries (per-instrument series merged on the union of timestamps, carrying each holding forward so gaps don't carve false dips). All pure and unit-tested; not yet surfaced in the UI
- Shared UI primitives extracted for reuse across screens: the range selector moves to the design system with its range logic (parse, filter) pulled into a pure, tested module; the invested-vs-value chart body is split from the instrument card so the same shape serves a single holding and the whole portfolio; plus a greyscale donut, a stat tile and shared signed-figure helpers
- Summary screen, now the home route (holdings move to /cartera): headline portfolio value with its change over the selected range, portfolio evolution chart, invested/unrealized/realized/position tiles, allocation donut by instrument type, and the five largest holdings. The range selector lives in the header and is driven by URL search params, so a ranged view is shareable and survives a reload. The headline change reports the movement in unrealized P&L rather than in market value, so a contribution is not mistaken for a gain. Holdings without a usable base-currency price are excluded from the totals and reported in the hero instead of being silently dropped
- Historical price backfill: pnpm prices:backfill [ISIN] [range] fetches daily closes from Yahoo and persists them, so charts can draw the past instead of starting at the first sync. Deliberately skips the freshness filter that prices:sync applies — every candle is old by definition, and discarding old quotes is right for "what is this worth now" and wrong for "what was it worth then". Requests are sequential to stay under the unofficial endpoint's rate limits, and re-runs upsert on (instrument, quote time) rather than duplicating. New tested pure parser for the close series, which drops sessions with no close rather than interpolating a price that never traded
### Fixed
- Contributions now count purchase fees, matching the cost basis used everywhere else. The KPI tile summed gross amounts only, so it disagreed with the P&L header by exactly the fees paid — 1 EUR on a single-purchase holding. Fees are money that left the account and belong in the acquisition value under foral tax rules; excluding them understated contributions and flattered returns, so reported returns now move slightly against the holder and are correct
- The summary hero's all-time change is read from the same figures the tiles render rather than differenced off the ends of the series. The series starts at the first purchase, when P&L is already negative by the fees, so differencing handed those fees back as a gain and put the hero 1 EUR above the P&L tile. Before the first purchase there was no portfolio, so all-time change is current P&L and the two now agree by construction
- The latest price per instrument now resolves by market time rather than by fetch time. Ordering by fetch time was safe only while every write was a single current quote; a bulk history write lands hundreds of candles with the same fetch time, which would have surfaced an arbitrary years-old price as current and corrupted every valuation in the app
